# Дорожная карта проекта: MyGemini Zero v2 (Roadmap)

## 📌 Статус проекта: [В РАЗРАБОТКЕ / ИНИЦИАЛИЗАЦИЯ]
* **Начало:** Сентябрь 2026 г.
* **Архитектурный фокус:** Высокая производительность (`aiogram 3`, async SQLAlchemy), потоковый вывод ответов (Streaming), безопасный Zero-Knowledge контур, 100% обратная совместимость данных и платежей.

---

## 🗺️ Этапы реализации

```
[Этап 1: Фундамент] ──────> [Этап 2: Данные & ZK] ──────> [Этап 3: Gemini & Stream]
         │                              │                                │
         ▼                              ▼                                ▼
[Этап 4: aiogram 3 & Pay] ──> [Этап 5: RAG & Files] ─────> [Этап 6: Миграция & Релиз]
```

### Этап 1: Архитектурный фундамент и Окружение
* [ ] Проектирование модульной структуры каталогов проекта.
* [ ] Создание файла зависимостей `requirements.txt` / `pyproject.toml` (`aiogram>=3.17.0`, `google-genai>=1.0.0`, `sqlalchemy[asyncio]>=2.0.0`, `aiosqlite>=0.20.0`, `cryptography>=43.0.0`, `bcrypt>=4.2.0`).
* [ ] Настройка конфигуратора `settings.py` на `pydantic-settings` с валидацией `.env`.
* [ ] Создание файла `docker-compose.yml` и `Dockerfile` для лёгкого self-hosted запуска.
* [ ] Настройка структурированного логирования.

### Этап 2: База данных и Zero-Knowledge криптография
* [ ] Описание декларативных моделей SQLAlchemy 2.0 (`User`, `Dialog`, `Conversation`, `UserProfile`, `AppSettings`).
* [ ] Реализация асинхронной сессии БД (`get_async_session`) без глобальных блокировок.
* [ ] Реализация криптографического модуля (`crypto_service.py`):
  * Точная деривация ключей через PBKDF2 (480 000 итераций) для 100% совместимости с v1.
  * Работа с солью (`encryption_salt`) и Fernet.
  * Верификация bcrypt-хешей мастер-пароля и пароля паники.
* [ ] Реализация репозиториев для пользователей, диалогов и истории сообщений.

### Этап 3: Сервис Google Gemini и Потоковая генерация (Streaming)
* [ ] Интеграция официального `google-genai` SDK.
* [ ] Реализация генерации ответа в потоковом режиме (`generate_content_stream`).
* [ ] Реализация умного троттлера редактирования сообщений в Telegram (интервал 1.0–1.2 сек) с учётом лимитов Telegram Bot API (Flood control).
* [ ] Поддержка мультимодальности (обработка фото и голосовых сообщений).
* [ ] Подключение инструментов: `google_search` и `code_execution` (Python sandbox).

### Этап 4: Роутинг, FSM и Платёжный шлюз
* [ ] Реализация машины состояний `StatesGroup` для авторизации, настроек и диалогов.
* [ ] Разработка middleware для проверки сессии и автоблокировки по тайм-ауту (`session_ttl`).
* [ ] Перенос и регистрация платёжного шлюза:
  * Обработчик команды покупки/продления подписки (`send_invoice`).
  * Обработчик `pre_checkout_query`.
  * Обработчик `successful_payment` с продлением срока в БД.
* [ ] Роутеры команд (`/start`, `/logout`, `/reset`, `/history`, `/settings`, `/dialogs`, `/usage`, `/mydata`).
* [ ] Интерактивные меню на `InlineKeyboardMarkup` с `CallbackData`.

### Этап 5: Векторная память (RAG) и Мультидокументы
* [ ] Асинхронный адаптер векторного хранилища (ChromaDB / Qdrant) с коллекциями `dialog_{dialog_id}`.
* [ ] Поддержка загрузки документов: снятие лимита только на `.txt/.md`, добавление парсинга **PDF, DOCX, CSV**.
* [ ] Добавление интерактивного UI: просмотр списка запомненных фрагментов текущего диалога и удаление конкретных чанков.
* [ ] Механизм архивации старых сообщений диалога в суммаризированные чанки.

### Этап 6: Миграция данных, Регрессионное тестирование и Релиз
* [ ] Скрипт валидации существующей базы данных `bot_database.db` и векторного каталога `vector_store/`.
* [ ] Комплексный сквозной тест:
  * Разблокировка старого пользователя его существующим мастер-паролем.
  * Расшифровка старой истории и API-ключа.
  * Проверка доступности активной подписки.
  * Поиск по старой векторной памяти диалога.
  * Проведение тестового платежа.
* [ ] Подготовка документации для развертывания и обновления.
