# План переработки проекта: MyGemini Zero v2

## 1. Цели и задачи модернизации
Главная цель — создать производительную, масштабируемую и модульную версию бота **MyGemini Zero v2**, устранив технический долг первой версии, сохранив при этом 100% совместимость с уже существующими данными пользователей, криптографическим контуром Zero-Knowledge и текущим платёжным шлюзом.

### Ключевые требования:
1. **Сохранение платежей:** Текущий токен Telegram Payments API (`PAYMENT_PROVIDER_TOKEN`) и подписки пользователей продолжают работать без перенастройки в банке или BotFather.
2. **Сохранение безопасности Zero-Knowledge:** Все существующие мастер-пароли пользователей, криптографические соли (`encryption_salt`), пароли паники и зашифрованные ключи API остаются валидными.
3. **Бесшовный перенос данных:** Сохранение структуры пользователей, диалогов, истории сообщений и векторных эмбеддингов.
4. **Современный стек:** Переход с устаревшего `pyTelegramBotAPI` на **`aiogram 3.x`**, переход на официальный **`google-genai` SDK**, оптимизация асинхронной работы с базой данных.

## 2. Архитектурные изменения (Что меняем)

### 2.1. Telegram Bot Framework (`aiogram 3.x`)
* **Замена:** `pyTelegramBotAPI` (`telebot`) -> `aiogram 3.x`.
* **Маршрутизация:**
  * Замена сравнения локализованных строк на кнопках (`ALL_BUTTON_TEXTS`) на строгие `Router` и Pydantic-схемы `CallbackData`.
  * Разделение обработчиков по отдельным независимым модулям:
    * `handlers/auth.py` (Zero-Knowledge онбординг, разблокировка, блокировка, смена пароля).
    * `handlers/chat.py` (текст, фото, голос, потоковый вывод).
    * `handlers/dialogs.py` (создание, переключение, переименование, удаление).
    * `handlers/settings.py` (выбор модели, персоны, стиля, языка).
    * `handlers/payments.py` (инвойсы, pre-checkout, successful_payment).
    * `handlers/memory.py` (просмотр, удаление чанков, загрузка документов).
    * `handlers/admin.py` (панель управления, рассылки, статистика).
* **FSM (Состояния):** Машины состояний через `StatesGroup` (вместо строковых констант).

### 2.2. База данных и ORM
* **Замена:** Ручной `sqlite3` с блокировкой `db_lock = asyncio.Lock()` в одном файле на **SQLAlchemy 2.0 (Async) + aiosqlite / asyncpg**.
* **Миграции:** Подключение **Alembic** вместо ручных `PRAGMA table_info` и `ALTER TABLE`.
* **Модели данных:** Декларативные модели (`User`, `Dialog`, `Conversation`, `UserProfile`, `AppSettings`).
* **Бинарная совместимость:** Хранение полей `master_password_hash`, `encryption_salt`, `panic_password_hash`, `api_key` строго в бинарном формате (`LargeBinary` / `BLOB` / `BYTEA`) без искажения байтов.

### 2.3. Векторное хранилище и RAG (Память)
* **Архитектура:** Изоляция векторного движка от основного цикла событий бота.
* **Совместимость:** Поддержка коллекций формата `dialog_{dialog_id}` с 768-мерными эмбеддингами (`gemini-embedding-001`).
* **Новые возможности:** Добавление гранулярного CRUD для чанков памяти (пользователь может просматривать и удалять конкретные воспоминания).

### 2.4. Интеграция с Google Gemini
* **Замена:** 500+ строк самописных HTTP-запросов через `aiohttp` на официальный **`google-genai` SDK**.
* **Потоковая генерация (Streaming):** Реализация выдачи ответа в реальном времени через редактирование Telegram-сообщения с троттлингом (интервал ~1 секунда) для избежания лимитов Telegram API.
* **Инструменты:** Поддержка `google_search` и добавление `code_execution` (интерпретатор Python от Google).

## 3. План реализации по фазам

1. **Фаза 1: Скелет проекта и Окружение**
   Развертывание новой структуры каталогов, настройка зависимостей (`requirements.txt`), Docker-окружения (`docker-compose.yml`) и конфигурации.
2. **Фаза 2: Слой данных и Криптография ZK**
   Реализация криптографического ядра (деривация PBKDF2, совместимая с первой версией, и Fernet), асинхронных моделей SQLAlchemy и репозиториев БД.
3. **Фаза 3: Интеграция Gemini SDK и Streaming**
   Сервис Gemini на `google-genai` SDK с поддержкой стриминга, токенизации, мультимодальности (фото/голос) и системных промптов.
4. **Фаза 4: Роутеры aiogram 3 и Платежи**
   Создание роутеров `aiogram 3`, перенос платёжного шлюза, реализации FSM и ZK-авторизации с тайм-аутом сессий.
5. **Фаза 5: RAG Память и Документы**
   Модернизация менеджера памяти (RAG), поддержка загрузки PDF/DOCX и интерфейс управления воспоминаниями.
6. **Фаза 6: Миграция данных и Тестирование**
   Прогон тестовой миграции существующей базы `bot_database.db`, регрессионное тестирование и запуск.
