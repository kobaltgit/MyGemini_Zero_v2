* **Шаги для воспроизведения:** 1, 2, 3...

* **Ссылка на решение:** Ссылка на запись в `BUG_TRACKER.md`

### Подробные карточки зарегистрированных дефектов

#### [BUG-003] Краш по TelegramBadRequest: message is not modified
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Blocker
* **Статус:** New
* **Компонент:** UI / Callbacks
* **Описание:** При нажатии кнопки «Назад» (`back_to_main`, `menu_settings`, `dialog_list` и др.) или повторном нажатии активного элемента меню вызывается `callback.message.edit_text(...)` без проверки на совпадение разметки и без перехвата исключения `TelegramBadRequest`.
* **Шаги воспроизведения:**
  1. Открыть `/settings` или `/dialogs`.
  2. Нажать кнопку «Назад» или выбрать уже активный диалог / модель.
  3. Получить исключение в логах: `Bad Request: message is not modified`.
* **Ожидаемый результат:** Сообщение либо обновляется, либо исключение подавляется с гашением спиннера через `callback.answer()`.
* **Фактический результат:** Хэндлер падает, апдейт сбрасывается, на кнопке вечно вращаются «часики».

#### [BUG-004] Зависание в FSM-состояниях при выходе из меню (FSM State Trap)
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Blocker
* **Статус:** New
* **Компонент:** FSM / Navigation
* **Описание:** В обработчиках `handle_close_menu`, `handle_back_to_main`, `handle_dialog_list` отсутствует очистка `await state.clear()`. Пользователь, открывший меню ввода (переименование диалога, ввод ключа/пароля, анкета, рассылка) и нажавший «Закрыть» или «Назад», навсегда остаётся в этом состоянии FSM. Любой последующий текст в чат перехватывается старым состоянием.
* **Шаги воспроизведения:**
  1. В списке диалогов нажать `✏️` (переименовать диалог).
  2. Нажать кнопку «❌ Закрыть» или «⬅️ Назад к диалогам».
  3. Написать в чат обычный запрос к AI.
* **Ожидаемый результат:** Запрос отправляется в модель Gemini.
* **Фактический результат:** Сообщение перехватывается состоянием `DialogStates.waiting_for_rename`, диалог переименовывается в текст запроса, ответа от AI нет.

#### [BUG-005] Полное исчезновение навигационных кнопок на экранах ввода
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Major
* **Статус:** New
* **Компонент:** UI / Navigation
* **Описание:** В `handlers/auth.py` при вызове `vault_unlock_chat_prompt`, `vault_setup_chat_prompt`, `api_key_chat_prompt` и в `handlers/profile.py` при заполнении анкеты метод `edit_text` вызывается без `reply_markup`. Кнопки «Назад» и «Закрыть» физически удаляются из сообщения, пользователь не может отменить действие.
* **Ожидаемый результат:** На всех экранах ожидания ввода присутствует инлайн-кнопка «⬅️ Отмена / Назад» и «❌ Закрыть».
* **Фактический результат:** Кнопки исчезают, выйти из состояния без ввода невозможно.

#### [BUG-006] «Мёртвые» inline-кнопки без обработчиков
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Major
* **Статус:** New
* **Компонент:** UI / Callbacks
* **Описание:** Кнопка «🚨 Настроить паник-пароль» (`settings_panic`) в меню настроек и кнопка «📦 Архивировать старые сообщения» (`memory_archive_start`) в меню памяти объявлены в разметке, но не имеют зарегистрированных хэндлеров в роутерах. Нажатие приводит к вечному спиннеру.
* **Ожидаемый результат:** Открытие меню настройки паник-пароля и запуск архивации соответственно.
* **Фактический результат:** Зависание кнопки, отсутствие реакции бота.

#### [BUG-007] Перехват команды /start в commands_router блокирует онбординг
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Critical
* **Статус:** New
* **Компонент:** Handlers / Routing
* **Описание:** В `handlers/__init__.py` `commands_router` зарегистрирован раньше `start_router`. Обработчик `handle_start_command` перехватывает `/start`, отправляет Reply-клавиатуру и никогда не передаёт управление в `start.py`, где находится логика первичной установки мастер-пароля и разблокировки хранилища.
* **Ожидаемый результат:** Новый пользователь проходит ZK-онбординг с обязательной установкой мастер-пароля.
* **Фактический результат:** Новый пользователь видит приветственный текст и Reply-меню в обход обязательного онбординга.

#### [BUG-008] Полная утрата двуязычности (RU / EN)
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Critical
* **Статус:** New
* **Компонент:** Localization / i18n
* **Описание:** Из проекта v2 удален модуль `localization.py` и файл со словарями переводов на 712 строк. Все строки в клавиатурах, хэндлерах и промптах захардкожены на русском языке. В меню настроек вырезана кнопка смены языка.
* **Ожидаемый результат:** Поддержка 100% двуязычности (интерфейс, кнопки, системные ошибки и ответы модели на RU / EN) с переключением в Настройках.
* **Фактический результат:** Бот исключительно русскоязычный, смена языка невозможна.

#### [BUG-009] Утрата двухэтапного подтверждения паролей
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Critical
* **Статус:** New
* **Компонент:** Auth / Crypto
* **Описание:** В v1 при установке мастер-пароля и паник-пароля бот обязательно запрашивал повторный ввод для верификации. В v2 пароль сохраняется с первого ввода в чат. Любая опечатка навсегда блокирует доступ к Zero-Knowledge хранилищу пользователя.
* **Ожидаемый результат:** Двухэтапная установка с валидацией совпадения паролей.
* **Фактический результат:** Сохранение с одной попытки без подтверждения.

#### [BUG-010] Отсутствие личных уведомлений администратора в Telegram
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Major
* **Статус:** New
* **Компонент:** Payments / Admin
* **Описание:** При поступлении оплаты через Telegram Payments в `handlers/subscription.py` выполняется только локальное логирование. Уведомление в ЛС админу с деталями платежа не отправляется. Аналогично не отправляется уведомление о новом пользователе.
* **Ожидаемый результат:** Администратор мгновенно получает оповещение в ЛС при успешной оплате и регистрации.
* **Фактический результат:** Оповещения в Telegram отсутствуют.

#### [BUG-011] Утрата расширенных инструментов администрирования пользователей
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Major
* **Статус:** New
* **Компонент:** Admin Panel
* **Описание:** В v2 вырезано персональное управление пользователями: просмотр данных по User ID, кнопка блокировки/разблокировки, сброс API-ключа пользователя, ручное продление подписки на 30/90/365 дней и ответ пользователю через бота.
* **Ожидаемый результат:** Панель администратора содержит подменю управления пользователями.
* **Фактический результат:** Доступна только статичная текстовая сводка подписчиков и выгрузка CSV.

#### [BUG-018] Рассинхронизация и дублирование Reply-клавиатуры и Inline-меню
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Normal
* **Статус:** New
* **Компонент:** UI / UX
* **Описание:** Нажатие на Reply-кнопку («⚙️ Настройки») порождает отдельное сообщение с инлайн-кнопками. Кнопка «⬅️ В главное меню» внутри этого сообщения перерисовывает его в копию главного меню, дублируя нижнюю клавиатуру.

#### [BUG-019] Отсутствие буферизации/дебаунса входящих сообщений
* **Дата обнаружения:** 2026-09-16
* **Критичность:** Normal
* **Статус:** New
* **Компонент:** Chat / Media
* **Описание:** В v1 пакетные сообщения и альбомы фото агрегировались через `_process_buffered_messages_task`. В v2 каждое сообщение обрабатывается немедленно, что при отправке медиа-групп может приводить к гонке запросов к Gemini API.

#### [BUG-022] Отсутствие модального окна ввода пароля WebApp и подтверждения при регистрации
* **Дата обнаружения:** 2026-09-17
* **Критичность:** Major
* **Статус:** Resolved
* **Компонент:** UI / WebApp
* **Описание:** Модальное окно Telegram Mini App было отключено из-за ограничения Telegram Bot API (метод `sendData` не работает из инлайн-кнопок). В статической веб-форме отсутствовало поле подтверждения пароля, создавая риск опечатки при регистрации. Нижняя клавиатура не адаптировалась под заблокированное состояние.
