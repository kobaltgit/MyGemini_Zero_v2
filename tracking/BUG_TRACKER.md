# Журнал исправления багов: MyGemini Zero v2 (Bug Tracker)

> Файл для глубокого анализа первопричин (RCA), описания применённых инженерных решений и верификации исправленных ошибок.

## Регламент работы с багом:
1. Баг регистрируется в `BUGS.md` с присвоением `BUG-XXX`.
2. Когда начинается работа, статус меняется на `In Progress`.
3. В этом файле (`BUG_TRACKER.md`) создаётся запись:
   * **Root Cause Analysis (RCA):** В чём была фундаментальная причина сбоя.
   * **Solution & Code Changes:** Какие файлы и функции были изменены и почему.
   * **Verification / Test:** Как было подтверждено исправление (тесты, ручная проверка).
4. Статус бага в `BUGS.md` переводится в `Resolved`.

### [FIX-BUG-003] Исправление: Исключение TelegramBadRequest «message is not modified»
* **Дата закрытия:** 2026-09-16
* **Затронутые файлы:** `core/ui_helpers.py`, `handlers/commands.py`, `handlers/dialogs.py`, `handlers/settings.py`, `handlers/start.py`, `handlers/memory.py`
* **Первопричина (RCA):** Повторные нажатия пользователем на одну и ту же инлайн-кнопку либо клик «Назад» вызывали `callback.message.edit_text` с идентичным текстом и разметкой, что вызывало необработанное исключение Telegram API `message is not modified` и краш хэндлера.
* **Применённое решение:** Разработана функция `safe_edit_message_text`, которая подавляет `TelegramBadRequest` при отсутствии изменений в тексте/кнопках и гарантирует подтверждение коллбэка. Все роутеры переведены на этот хелпер.
* **Верификация (Тестирование):** Тест `test_safe_edit_message_text_suppresses_bad_request` в `tests/test_fixes_and_i18n.py`.

### [FIX-BUG-004] Исправление: Ловушки состояний FSM (FSM State Traps)
* **Дата закрытия:** 2026-09-16
* **Затронутые файлы:** `handlers/commands.py`, `handlers/start.py`, `handlers/dialogs.py`
* **Первопричина (RCA):** При выходе из диалоговых меню через «Закрыть», «В главное меню» или «Назад к диалогам» не вызывался `await state.clear()`. Пользователь навсегда оставался в состоянии ввода (например, переименование диалога или ввод пароля).
* **Применённое решение:** В обработчики `handle_close_menu`, `handle_back_to_main`, `handle_dialog_list` добавлен `state: FSMContext` и принудительный сброс состояния `await state.clear()`.
* **Верификация (Тестирование):** Проверено сквозным сценарием отмены ввода и прогоном всех unit-тестов.

### [FIX-BUG-020] Исправление: Блокировка команд из-за синтаксиса фильтра Command в aiogram 3
* **Дата закрытия:** 2026-09-17
* **Затронутые файлы:** `handlers/guide.py`, `handlers/feedback.py`, `handlers/commands.py`, `handlers/chat.py`
* **Первопричина (RCA):**
  В aiogram 3 несколько фильтров, переданных в декоратор через запятую `@router.message(f1, f2)`, объединяются логическим `AND`. Запись `@router.message(Command("guide"), Command("help_guide"))` требовала, чтобы команда была одновременно и `guide`, и `help_guide`, что физически невозможно. В результате `/guide`, `/feedback`, `/profile` и `/documents` не срабатывали и проваливались в fallback-роутер `chat.py`.
* **Применённое решение:**
  1. Синтаксис фильтров исправлен на объединение команд внутри одного объекта: `Command("guide", "help_guide")`, `Command("feedback", "support")`, `Command("profile", "account")`, `Command("documents", "memory")`.
