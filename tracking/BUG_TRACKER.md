# Журнал исправления багов: MyGemini Zero v2 (Bug Tracker)

> Файл для глубокого анализа первопричин (RCA), описания применённых инженерных решений и верификации исправленных ошибок.

## Регламент работы с багом:
1. Баг регистрируется в `BUGS.md` с присвоением `BUG-XXX`.
2. Когда начинается работа, статус меняется на `In Progress`.
3. В этом файле (`BUG_TRACKER.md`) создаётся запись:
   * **Root Cause Analysis (RCA):** В чём была фундаментальная причина сбоя.
   * **Solution & Code Changes:** Какие файлы и функции были изменены и почему.
   * **Verification / Test:** Как было подтверждено исправление (тесты, ручная проверка).
4. Статус бага в `BUGS.md` переводится в `Resolved`.

### Шаблон карточки исправления:

```markdown
### [FIX-BUG-XXX] Исправление: <Название бага>
* **Дата закрытия:** ГГГГ-ММ-ДД
* **Затронутые файлы:** `app/...`
* **Первопричина (RCA):** 
  Подробный разбор того, почему возникла ошибка (например: состояние гонки, рассинхронизация типов BLOB, превышение лимитов Telegram API).
* **Применённое решение:** 
  Описание изменений в архитектуре или коде.
* **Верификация (Тестирование):**
  - Шаги проверки
  - Результат прогона тестов
```
