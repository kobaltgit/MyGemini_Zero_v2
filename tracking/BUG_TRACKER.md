# Журнал исправления багов: MyGemini Zero v2 (Bug Tracker)

> Файл для глубокого анализа первопричин (RCA), описания применённых инженерных решений и верификации исправленных ошибок.

## Регламент работы с багом:
1. Баг регистрируется в `BUGS.md` с присвоением `BUG-XXX`.
2. Когда начинается работа, статус меняется на `In Progress`.
3. В этом файле (`BUG_TRACKER.md`) создаётся запись:
   * **Root Cause Analysis (RCA):** В чём была фундаментальная причина сбоя.
   * **Solution & Code Changes:** Какие файлы и функции были изменены и почему.
   * **Verification / Test:** Как было подтверждено исправление (тесты, ручная проверка).
4. Статус бага в `BUGS.md` переводится в `Resolved`.

### [FIX-BUG-001] Исправление: Залипание inline-кнопок на смартфонах
* **Дата закрытия:** 2026-09-16
* **Затронутые файлы:** `handlers/commands.py`, `handlers/dialogs.py`, `handlers/settings.py`, `handlers/start.py`, `handlers/memory.py`, `handlers/profile.py`
* **Первопричина (RCA):**
  На мобильных клиентах Telegram (Android/iOS) при клике по inline-кнопке запускается локальный таймер ожидания ответа сервера на `callback_query_id`. Если бот выполняет `message.delete()` до вызова `callback.answer()`, мобильный клиент считает коллбэк осиротевшим/невалидным и блокирует кнопку («часики» не гаснут). При последующих нажатиях повторные события не обрабатываются.
* **Применённое решение:**
  1. В `handle_close_menu` вызов `callback.answer()` гарантированно вызывается до `message.delete()`.
  2. Во всех навигационных обработчиках подтверждение коллбэка вынесено в самое начало методов с перехватом исключений, исключая задержки интерфейса.
* **Верификация (Тестирование):**
  - Автоматические тесты `test_new_features.py` успешно завершены.

### [FIX-BUG-002] Исправление: Отсутствие контекстной шапки в стриме ответов
* **Дата закрытия:** 2026-09-16
* **Затронутые файлы:** `services/throttler.py`, `handlers/chat.py`, `tests/test_new_features.py`
* **Первопричина (RCA):**
  При переносе генерации в v2 на потоковый стриминг через `MessageStreamThrottler` блок формирования контекстной шапки (`Диалог`, `Персона`, `Модель`) не был интегрирован в поток и итоговое сообщение Telegram.
* **Применённое решение:**
  1. В `MessageStreamThrottler` добавлен параметр `header_text`, отображающий шапку в первом сообщении ответа.
  2. При вызове `finalize()` возвращается чистый текст модели для сохранения в БД без замусоривания истории диалога.
  3. В `handlers/chat.py` реализовано извлечение названия активного диалога, имени персоны на русском и модели Gemini.
* **Верификация (Тестирование):**
  - Разработан и пройден автотест `test_throttler_with_context_header`.
